# 自托管云端材料存储

依据：[已确认需求](cloud-sync-design.md)、[并发冲突决策](adr/0001-cloud-sync-conflict-policy.md)。云服务部署在用户自己的 Debian 主机上，本仓库同时包含本地客户端与独立服务端实现；部署现状见[部署说明](../deploy/cloud/README.md)。

## 实现结构

- `backend/video_parser/cloud/`：独立 FastAPI 服务，标准库 SQLite 保存账号、会话摘要、项目 revision、材料版本、幂等结果；私有磁盘保存按内容哈希验证的文件。
- `backend/video_parser/services/cloud_sync.py`：本机账号会话、账号/视频库隔离的持久队列、上传快照、自动对账、下载与恢复。
- `backend/video_parser/services/cloud_materials.py`：允许类型和字段的导出、引用转换、哈希校验及非覆盖导入。
- `backend/video_parser/web/cloud_routes.py`：现有本地工作台中的 JSON 接口，继续受 `local_request` 限制。
- `frontend/src/features/settings/CloudStorage.tsx`：设置中的“登录与云端存储”，提供选择上传、自动同步、独立云端副本、重复关联、版本、传输记录和回收站。
- `backend/video_parser/web/local_media_routes.py`：本机视频选择、异步校验、取消和进度接口，始终受 `local_request` 限制。

云服务与本地工作台是两个进程。云端不加载本机任务、平台 Cookie、AI 配置或视频处理接口，不向公网开放现有本地工作台。复用现有 FastAPI 等依赖，没有增加数据库、前端云 SDK 或认证依赖。SQLite 与文件目录必须在服务器本地磁盘。

## 账号和材料边界

管理员通过交互命令创建账号，没有默认账号或公开注册。服务端使用带盐 scrypt 和有期限的随机令牌；只保存令牌摘要。客户端密码不落盘，令牌只在本地后端内存中，本机后端重启后需要重新登录。登录名支持邮箱或普通用户名（如 `Celyn`），唯一性大小写不敏感。

只导出已登记且允许的字幕、转录、校对、翻译、AI 结果、封面、图片、画面帧、对话及其明确引用的图片。视频、音频、临时任务文件、运行配置、Cookie 和 API Key 不在导出清单。元数据与引用采用字段白名单；本地路径转换为材料/版本 ID。用户写入正文中的内容仍作为用户材料保存，并非对正文进行通用脱敏。

当前图片支持 PNG、JPEG、WebP；GIF 会明确报错，不能静默丢失。服务端验证哈希、实际图片内容、UTF-8/JSON 格式、大小和配额。初始限制为单文件 32 MiB、文字 4 MiB、账号文件总量 2 GiB、单次提交 200 个版本。大型项目分批提交版本，并持久化批次及幂等请求；超出单文件或账号限制会明确报错。

## 上传、并发与版本

1. 首次登录后勾选本地项目，选择单次上传或自动同步。未选项目不上传。
2. 上传取得校验过的材料快照，写入本地 SQLite 队列。工作线程进行文件传输；本机生成任务仍独立运行。
3. 服务端不可变文件发布和 SQLite 事务保护版本、revision 与操作结果；本地文件锁只负责本机发布。
4. 每个提交携带基准 revision 和 operation ID。响应丢失时保持同一请求重试；确定 revision 冲突后重新读取，再以新操作追加可安全保留的版本。
5. 同槽位的不同内容保留独立版本。首次提交初始化当前版本，后续上传不自动切换；用户可明确选择云端当前版本。
6. 本机已有资源继续保留，新电脑优先按云端当前版本初始化。标题和学习状态按基准值对账，冲突保留双方值。

本机使用单个传输工作线程，项目清单提交自然串行；不同电脑各自有队列，跨设备安全依靠服务器事务。没有跨设备计算调度、生成进度同步或任务接管。

默认云端项目 ID 沿用来源确定的本地项目 ID，同源视频默认复用，B站分 P 独立识别。“上传为独立项目”创建独立云端副本，不重命名原本地项目。明确关联重复项目时检查来源并保留双方材料。云端项目与本地项目单独映射，账号切换不会自动使用另一账号的映射或令牌。

## 下载、离线与退出

登录后后台获取项目列表、文字与状态；图片登记为云端占位，访问时校验下载，亦可选择“下载全部材料”。原资源读取、对话附件读取及归档检查已接入占位处理，尚未下载的图片不会被误报为本机文件丢失。下载校验通过后才发布，本地不同内容保留副本。

退出登录停止同步，保留本地材料和该账号未完成队列；重新登录同一账号后恢复。切换视频库停止旧库同步并清除内存会话。已下载材料可离线使用，需要视频本体的处理仍须在本机准备视频。

云端删除写入 tombstone、递增 revision，30 天内可恢复。本地文件保留，旧设备上传不能复活已删项目；未上传修改仍留在本机和上传快照中。到期回收保留项目身份 tombstone，避免离线旧操作重新创建。活跃项目历史版本没有自动过期策略。缓存清理和云端删除分开；本版本未新增自动图片缓存淘汰功能。

## 本地接口

全部位于 `/api/workspace/cloud`，请求 JSON，本地后端代传文件。

| 接口 | 用途 |
| --- | --- |
| `GET /session`、`POST /login`、`POST /logout` | 账号会话；登录收 `{login,password}`（兼容 `{email,password}`） |
| `GET /projects` | 本地项目、云端项目和同步状态 |
| `POST /upload`、`POST /sync-mode` | 单次上传或自动同步 |
| `POST /associate`、`POST /resolve-metadata` | 关联同源项目、明确处理标题或学习状态冲突 |
| `POST /pull` | 下载文字或全部材料 |
| `GET /transfers`、`POST /transfers/retry`、`POST /transfers/cancel` | 持久传输队列；每条含项目标题、动作、状态、尝试次数、创建/开始/结束时间、下次重试时间和材料摘要（版本数、字节数、基于修订、冲突字段等），不含本机路径或令牌 |
| `GET /versions`、`POST /select-version`、`POST /image` | 版本查看、选择与按需下载 |
| `POST /delete`、`POST /restore` | 回收站 |

服务端精确协议与启动命令见 [部署说明](../deploy/cloud/README.md)。

## 无链接本地视频

`local` 项目以视频内容 SHA-256 作为身份。云端同步字幕、转录、AI 结果、封面、图片、对话和状态，不同步视频本体、本机绝对路径或凭据。登录刷新会拉取账号下全部云端项目，因此新设备可先看到没有本机视频的资料占位；文字资料可查看，图片按需下载。

项目列表分别展示来源类型、资料状态和本机视频状态。无链接项目显示“本地视频未关联”；导入相同内容的视频时按哈希绑定到已有项目，文件名和路径可以不同，内容不同则拒绝关联。关联任务在本机临时目录分块复制、校验 SHA-256、验证视频轨道后再登记，支持取消、库根/账号切换检查和锁内禁止覆盖。视频关联不会自动触发云端上传，用户仍可单独选择是否同步资料。

本地关联接口为 `/api/workspace/local-media/picker`、`/start`、`/tasks/{id}` 和 `/tasks/{id}/cancel`。Windows 桌面环境可使用本机文件对话框，浏览器环境可传入用户选择的绝对路径。

## 部署与真机验证

已部署到用户的 Debian 13 主机：独立 `video-parser-cloud.service`（用户级 systemd，`/home/work/apps/video-parser-cloud`，数据目录 `data/`，监听 8090，Debian 官方包 fastapi/uvicorn/pillow，`PYTHONPATH` 指向安装目录）；正式账号由服务端 `create-user` 交互创建，无内置账号或默认密码。登录名可以是邮箱，也可以是 `Celyn` 这样的普通用户名（2–64 位字母/数字/`.`/`_`/`-`，首字符为字母或数字），大小写不敏感但保留原写法；已有邮箱账号可用 `rename-user <旧名> <新名>` 改名且不影响其数据。当前账号为用户要求的用户名 `Celyn`（由原邮箱账号改名而来）。

界面的登录字段是「用户名」，提交 `{server, login, password}`；服务端同时兼容旧的 `{email, password}` 请求体，旧客户端升级前仍可登录。

计划中的域名 HTTPS 入口 `sync.celyn-blog.top`（Caddy + Let's Encrypt 证书正常）被腾讯云按未备案域名劫持：HTTP 返回 302 到备案拦截页，443 被重置。因此按用户决定改为 **HTTP + 端口直连**：`normalize_server` 已允许公网 `http://`，仍拒绝带账号、路径、参数、片段或其他协议；本地界面填写 `http://110.42.237.129:8090`。明文 HTTP 会暴露 Bearer 令牌与材料内容，部署说明已记录该风险与优先恢复 HTTPS 的建议。

真机端到端（同一账号、两个独立视频库根）：

- 第一设备登录成功，上传项目 `a95b75b7…`，云端 revision 3、37 份材料；随后自动对账任务全部 `completed`。
- 第二设备使用独立 `VIDEO_LIBRARY_ROOT` 启动，登录后自动生成云端映射项目 `c6877099…`，拉取 37 份材料的文字/封面/分析，帧图片保留按需占位；列表显示 `has_local_video=false`、`source_kind=remote`、`cloud_material_count=37`。
- 按需下载图片：用云端项目 ID + 材料/版本 ID 触发 `POST /api/workspace/cloud/image`，任务 `completed`，第二设备写入 14073 字节 JPEG 并清除占位。首次使用本地项目 ID 报「云端项目或材料不存在。」，属预期接口约定（该动作按云端项目 ID 寻址），已在验证中确认。

部署期修复：Windows 上 `library.atomic_json` 的 `os.replace` 会与其他读取方产生瞬时 `WinError 5`，导致自动对账随机失败；已改为最多 20 次、50ms 间隔的有界重试，并补了瞬时/永久失败的离线回归。

## 自动化验证

在项目虚拟环境 Python 3.12.13 中，云存储专项测试全部通过（云服务端协议、本地同步、本地视频关联、占位归档检查与真实 HTTP 多进程集成）。真实网络集成使用临时 Uvicorn 服务及三个独立设备进程，验证同源并发上传保留三个版本；另外验证重复上传、新设备当前版本恢复、图片按需下载及退出登录/账号隔离。

完整离线回归 **769 项通过，跳过 1 项**（其中 `tests/offline` 含既有全部前端与后端离线检查）。国际化专项 5 项、前端 TypeScript 检查、生产构建均通过；构建仍提示现有 JavaScript 分块超过 500 kB。另一次全量出现过字幕测试间歇失败，单独字幕回归及最终全量复验均通过，未据此修改字幕实现。

协议复核修复了合法来源 URL 被当成本地路径拒绝、中文详情大小计算与服务端不一致，以及“正文相同但引用详情改变”导致不可变版本持续冲突的问题。新本地版本以内容与完整详情计算身份，并先确定被引用版本；已有云端版本身份保持不变。循环引用或过深引用在快照阶段明确报错，不会进入持续重试。自动对账异常不会阻塞其他项目或队列，已有相关回归。
